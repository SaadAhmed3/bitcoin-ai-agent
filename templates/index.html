                          Sources

                            Backtest & validation

                            Replays the live signal engine on real Binance history, bar by bar, with no look-ahead. Only the first holdout run in the current holdout period can lift the NO TRADE gate.

                            Hypothetical
                            What do these choices mean?
                            • Period: full = the whole test span, informational only: it includes the design data, so it can never validate; design = up to the holdout start, in-sample for rule research, can never validate; holdout = from the holdout start (shown in the list), reserved for one pre-registered test. The holdout is single-use: the first holdout run, whatever its rules, spends it. Later runs are stored but "not valid for validation"; a different rule set needs a new holdout start after the spent period (forward data only).
                            • Entry rule: standard = buy at the next open after a BUY setup; breakout / pullback = the pre-registered pending-order rules (Phase 6.2).
                            • Download: refreshes 1h/4h/1d Binance history first (about 60-80 free requests). A 4-year run takes roughly 5-10 minutes.
